# 알까기 — 온라인 2인 대전

방을 만들어 코드를 공유하면 상대가 들어와 시작한다. 돌 5개를 자기 진영에
직접 배치하고, 선공은 서버가 무작위로 정한다. 상대 돌 5개를 모두 판 밖으로
밀어내면 이긴다. 결과는 Elo 레이팅에 반영된다.

## 물리는 서버가 돌리지 않는다

서버는 **"어느 돌을 어느 방향으로 얼마만큼"** 만 중계한다. 양쪽 클라가 각자
같은 matter.js로 같은 입력을 돌리고, 돌이 멈추면 최종 상태 해시를 보고한다.
두 보고가 다르면 서버가 디싱크로 보고 판을 무효로 만든다.

혼자 클라를 고쳐도 상대 해시와 어긋나므로 승부를 조작할 수 없다. 서버에
물리 엔진을 올리지 않아도 되고, 오가는 데이터는 튕길 때마다 세 개의 숫자뿐이다.

**이 방식이 성립하는 조건은 하나다 — 같은 입력이 항상 같은 결과를 내야 한다.**
물리 갱신을 프레임 시간에 묶으면 60Hz와 120Hz 기기에서 결과가 갈라지므로,
`GameLoop`의 고정 스텝(1/60) 위에서만 `Engine.update`를 부른다. 이 규칙을
깨면 매 턴 디싱크가 뜬다.

내가 튕긴 값도 **서버를 거쳐 돌아온 뒤에 물리에 반영한다**(`onFlickRequest` →
서버 → `applyFlick`). 보낸 쪽만 자기 로컬 값을 바로 쓰면 미세하게 갈라진다.

## 물리 상수를 건드릴 때

`MAX_FLICK_SPEED = 17`은 임의값이 아니다. **돌 지름(48)보다 작아야 한다.**
matter.js에는 연속 충돌 검사가 없어서 한 스텝 이동 거리가 지름을 넘으면
돌끼리 그냥 통과한다. 돌이 5개라 배치가 촘촘해 이 위험이 크므로 올리지 않는다.

## 구조

```
src/
  game/AlkkagiGame.ts   물리·입력·렌더. matter.js가 새어나가지 않는 유일한 경계
  useMatch.ts           소켓 메시지 ↔ 게임 인스턴스. 화면은 phase와 snapshot만 본다
  screens/              인증 · 로비(랭킹) · 대국
  api.ts                서버 주소와 인증 클라이언트
```

서버 호출은 전부 `@gujuck/api`를 거친다. 이 앱은 `fetch`도 `WebSocket`도
직접 열지 않는다.

## 서버

`server/`(Spring Boot)가 필요하다. 포트 8090.

```bash
cd ../../server && docker compose up -d && ./gradlew bootRun
```

다른 주소를 쓰려면 `.env`에 `VITE_API_BASE`를 넣는다.
